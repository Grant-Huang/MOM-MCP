# G2 周期审计

Daily 和 Weekly 在默认分支定时运行，也支持手动补跑。工作流使用只读权限，报告保存在工件中。计划时间以 UTC 表示，Daily 每天 07:17，Weekly 每周一 08:41。

| 作业 | 调查窗口 | 证据与故障语义 |
|---|---|---|
| Daily | 同一默认分支上最近一次成功的 Daily SHA 到本次候选 SHA。首次从首提交开始 | 保存提交列表、路径风险报告和 P8B 回归。报告、测试或工件上传导致作业失败时，成功基线保持旧值；断跑后用手动触发补查 |
| Weekly | 从当前时间回溯七日，以首父历史中截止时刻之前的提交作为基线 | 输出契约、验收和其他变更线索及复核主题。结合 Daily 工件、审查结论和缺陷记录确认重复根因、补测或退役。缺失的独立发现和历史 CI 趋势明确记录为未知 |

两个报告采用窗口净差异评估路径风险，并列首父提交供复核被撤销或覆盖的中间变化。默认分支历史重写导致旧基线脱链时，Daily 报错。由维护者核对旧报告、历史及覆盖范围后处理。API 读取失败也使本次检查失败，空基线仅来自成功查询且无历史成功运行。

本地可执行 `node --test scripts/periodic-audit.test.mjs`，或用当前 SHA 运行 `node scripts/periodic-audit.mjs weekly "$(git rev-parse HEAD)"`。Daily 本地命令支持追加先前成功 SHA。GitHub 首次运行后核查工件、默认分支 SHA，以及失败补跑是否继续使用上次成功基线。语义审查和平台审批证据仍由相应负责人确认。 [独立审查试点](PR_REVIEW_PILOT.md)
