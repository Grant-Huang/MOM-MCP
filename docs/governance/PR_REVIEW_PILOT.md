# G2 PR 风险与独立审查试点

PR 事件触发只读作业，生成包含 base/head SHA、文件及理由的风险建议。报告作为工件保存。脚本接受明确 SHA，在 Git 合并基线和候选提交之间比较；重命名同时检查旧路径和新路径。可以在本地运行 `node scripts/pr-risk.mjs <base SHA> <head SHA>`。

路径只提供初判。纯说明可建议 R0，未经识别的内容按 R2 审阅。R1 由负责人根据可逆的局部影响确认；共享契约和验收证据建议 R2，控制面和 CI 路径建议 R3。确认人应结合实际 diff、依赖、业务状态和发布影响，记录调整理由。自动报告不提供审批证据，也不决定跳过哪些现有验收。

## 独立审查操作

1. 作者在 PR 中登记授权或特性、影响范围、候选 SHA、测试及未知项。以 P8B 工单预检和装配派工作为首个语义样本。
2. 独立审查者使用另一只读上下文，检查当前 diff、公开 schema 和对应验收。重点核对预检无写入、短缺和不适用工位的拒绝、派工重新检查，以及重试状态和历史场景兼容。
3. 按候选 SHA 记录结论和发现。每个发现列文件行号、最小复现、影响、严重度和新增或既有分类。高后果发现需另一名验证者或独立上下文复现。修订后明确复查的 SHA。
4. 负责人依据实际证据签收。缺少独立审查时标记待审，尤其当报告来自候选分支自带脚本时。可信来源的强制配置留待 G3。

本阶段提交风险报告、PR 模板和独立审查操作说明。已指派的独立审查结论、Daily 补跑基线以及 Weekly 报告属于后续 G2 交付。
