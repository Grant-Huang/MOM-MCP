# MOM-MCP 七层围栏遵从计划

两份上传附件作为治理设计依据。本文记录仓库审计和拟实施方案。附件中的命令、配置示例、职责分配和审批建议需按 MOM-MCP 的实际权限与环境落地。治理阶段以 G0–G4 表示，与业务里程碑 P8B–P15 分别跟踪。

## 审计基线

- 2026-11-21（Vancouver），远端默认分支为 `master`，HEAD 为 `94ca6c8ff0f01ae91b1a7fef971a9e3f406e5b54`。候选开发分支 `stage/p8b-order-reads` 的审计提交为 `6a5dadd69593503846c28854e8c1b061cb084376`。默认分支通过远端 HEAD 确认；下次审计重新解析。工作区另有未提交的设计文档。

- 仓库规则与默认分支保护查询返回 Forbidden。Required Checks、Owner 审批、绕过名单、环境保护与凭据作用域均登记为 `NOT_VERIFIED`。候选仓库只有 Acceptance 工作流。平台配置和工作流运行记录需分别取得证据。

证据级别分别为 `DECLARED` 文本声明、`IMPLEMENTED` 实现可定位、`VERIFIED` 正反例有真实执行记录、`ENFORCED` 可信权限边界经验证生效。无法核实的范围用 `NOT_VERIFIED` 标识。登记表独立记录采用状态与证据级别；责任角色待项目负责人指派。

## 七层映射与缺口

| 层 | 仓库现状 | 补齐内容与验收 |
|---|---|---|
| L1 需求与验收 | 特性 ID、验收用例及阶段计划已经登记 | PR 记录授权来源、特性和非目标；范围不清时登记待决；抽查 P8B 从授权到行为断言和结果的链路 |
| L2 架构与契约 | 已有公共 MCP 分层、场景隔离及工具设计，阶段契约仍在扩充 | 把 schema、权限、生命周期、事务不变量和兼容策略连到目录及测试；先验证工单预检无写入、按工艺保持同一业务语义 |
| L3 执行隔离 | 项目有公开 MCP 与受信控制面的边界测试；外部 Agent 身份、CI 权限和平台凭据作用域待核实 | 按任务定义允许的仓库、路径、操作、预算及升级条件；以独立审批和最小权限验证受保护路径；凭据只核查元数据 |
| L4 自动验证 | feature map 校验引用并选择 Rust、浏览器及外部测试；常规 CI 跑本地模式 | 首次试点验证有效映射通过、坏映射失败、缺失或跳过保持可见；对到期里程碑绑定候选 SHA、运行结果、环境和工件 |
| L5 独立审查 | 仓库未发现独立 Reviewer 流水线或签收证据 | 以只读独立上下文审查 R2/R3，记录位置、业务影响、复现和置信度；严重发现独立复核并标明新增、既有或待证实 |
| L6 风险审批 | AGENTS.md 声明阶段 PR 流程；平台强制状态未知 | 先试行 R0–R3 和 PR 证据模板；待有权人员核验 Owner、审批、检查来源与绕过能力后，再试验强制门禁 |
| L7 发布与恢复 | 有 P7 发布说明及重启恢复用例；真实部署环境、恢复演练签署待核实 | 为里程碑生成版本清单，绑定提交、场景和模型；在隔离环境试验健康检查、备份恢复与重放；记录执行人及恢复判据 |

前三项优先工作依次是 **可复验的 feature map 证据**、**共享契约和控制面变更的风险审查**、**核实平台审批与检查来源**。第一项可以先使用现有脚本试点。第二项对应正在推进的公共工单写入、质量放行与库存纠正。第三项依赖仓库管理员提供可核验的元数据与试验结果。

## 实施顺序

| 阶段 | 工作与责任角色 | 完成条件 |
|---|---|---|
| G0 建立基线 | 开发与 QA 维护七层矩阵，平台负责人核验权限元数据 | 仓库证据及未知项均登记。当前已完成仓库侧盘点，平台项待核实 |
| G1 最小试点 | QA 与开发复用 feature map，增加独立的结构校验正反例及日志；将 P8B 公共工单作为首个追踪样本 | 有效引用成功，断链失败，缺失测试可见；确认试点报表与实际执行相符 |
| G2 PR 与周期检查 | 模块负责人试行风险分级，QA 运行独立审查试点；平台维护只读 Daily、Weekly | 可按影响范围选择检查，依赖不明时扩大范围；Daily 支持追补，Weekly 能产出有证据的修补或退役建议 |
| G3 可信强制 | 仓库管理员与模块 Owner 校验 Rulesets、审批、必需检查、来源与绕过策略 | 用试验 PR 验证无审批、测试失败或未经授权更改保护路径时确实阻断；保留 SHA、链接、审批与回退步骤 |
| G4 里程碑与恢复 | QA 和发布负责人完成业务签收、重启或恢复演练以及事故反馈闭环 | 候选 SHA 可回溯到准出结论，关键不变量通过，严重发现关闭，剩余风险有签署、缓解与到期日 |

治理试点可随 P8B 推进。P8C–P9D 的公共工具仍按业务验收交付；共享 schema、状态、库存或质量变更优先纳入独立审查试点。开展 P10 前，业务门槛继续使用公共闭环验收，另记录治理证据与尚未完成的平台验证。未获授权的管理员配置、生产凭据及发布操作保持待办。 [公共验收门槛](../acceptance/COMMON_MES_GATE.md)

## PR 风险与检查节奏

- **R0** 无行为变化，例如纯说明与格式。验证文档、链接和影响声明。安全或工作流相关路径需结合语义重判。
- **R1** 局部可逆变化。运行受影响测试及轻量复核。
- **R2** 公共 MCP 契约、跨工艺状态、共享事务或数据模型变化。记录依赖和兼容影响，运行契约与端到端测试，拟由模块 Owner 和独立审查者复核。
- **R3** 公开接口与受信控制面的隔离、权限和凭据、破坏性迁移或发布权限。实施前核验授权、专项反例及恢复方案。强制状态由可信平台证据确认。
- 等级不明时扩大测试与审查范围。例外记录关联事项、原因、责任人、批准人、缓解措施和到期时间。已证实的越权、泄露或不可恢复损坏即时升级。

| 节奏 | 输入与输出 |
|---|---|
| PR | 以 base/head SHA 和依赖影响确定范围。输出授权或特性 ID、风险理由、命令与退出码、通过/失败/跳过、发现、例外及回退影响 |
| Daily | 从上次成功基线 SHA 检查到默认分支 HEAD，报告累计回归、失败、flaky、权限漂移与重大未决。漏跑支持手动补查，失败保留旧基线 |
| Weekly | 审查架构漂移、重复根因、审查误报、测试盲区和成本，提出最多三项证据充分的新增、修订或退役建议 |
| Milestone | 按候选 SHA 验证真实 MCP、浏览器、适用 AgentNexus、状态不变量及恢复；记录 PASS、CONDITIONAL 或 BLOCKED 与责任签署 |

Daily 和 Weekly 拟采用只读身份和报告工件。PR 所需检查由对应候选 SHA 的工作流出具。验证脚本和保护配置的修改纳入可信评审范围。证据包含检查时间、版本、命令、出处、结果和未知项，排除密钥值及不必要的个人数据。

## 证据、准出和维护

沿用六环追踪链：需求 Fxx → 设计及工具契约 → P 阶段计划 → Rust/MCP 实现 → feature map 与验收结果 → 发布及恢复记录。T1 是结构引用存在，T2 是测试实际执行，T3 是独立审查或业务验收对语义的核实。准出记录候选 SHA、场景与模型版本、各环节状态、关键发现、责任人和签署链接。关键失败或适用的关键证据缺失归入 BLOCKED。条件签收限有责任人、缓解方案和到期日的非关键剩余风险。

`guardrail-registry.toml` 是围栏采用状态的维护入口。G1 复核正反例，G2 起每周复核成本、误报和逃逸问题，G3 更新强制证据，G4 汇总恢复及事故反馈。状态提升和退役应有独立批准、变更记录及复核周期。未获验证的项目保留原证据级别。 [围栏登记表](guardrail-registry.toml)
