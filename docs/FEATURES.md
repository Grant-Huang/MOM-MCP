# MOM-MCP 设计需求与特性清单

MOM-MCP 是供 AgentNexus 的 Agent 调用的离散制造 mock MCP 服务。项目演示页介绍工具和场景。工厂观察、业务动作及模拟反馈均通过 MCP 完成。这里的「完整 MES 场景」指一条可执行、可验证的制造任务链，范围以行业验收矩阵为准。

服务端时钟、由 DES 计算事件发生时间、调用端定义场景、CNC 模型包独立于内核为已确认要求。表内数量指标、工具名称和实现顺序是设计基线，待实施验证。

| ID | 特性 | 可验收结果 | 阶段 |
|---|---|---|---|
| F01 | AgentNexus 接入 | 通过实际 AgentNexus 连接完成 MCP 初始化、工具发现、查询和一次写调用，结构化结果可供下一步使用 | P0–P1 |
| F02 | Carbon 式工具发现 | 按中英文同义词、业务域和读写属性搜索。描述与执行使用同一份 schema。搜索只返回当前场景可用工具 | P1 |
| F03 | 客户端定义场景 | 调用端提交版本化场景与模型参数，包含初始状态、分布、条件和业务约束。未知模型、非法参数及直接指定事件时刻的字段均被拒绝 | P1–P2 |
| F04 | 场景选择与隔离 | 支持列出、打开、切换和结束场景。两个 run 在同一连接交替调用时各自保留数据、时钟和游标 | P1 |
| F05 | 服务端共享仿真时钟 | 一个 run 内各 Agent、模型与 MES 工具观察同一条单调虚拟时间线。读操作不推进时间。控制端只指定执行预算或停止条件 | P2 |
| F06 | 规则生成离散随机事件 | DES 按分布、状态和触发规则抽样，跳到下一事件。同行为的重放保持事件顺序。干预可重排未来事件，已公开的历史稳定 | P2 |
| F07 | 服务端模型包 | CNC 模型从通用内核依赖图移出，按包 ID 和版本加载。可在无需修改内核的情况下注册另一行业模型 | P2–P4 |
| F08 | 一致的 mock 数据 | 从初始数据和已发生事件构建工单、WIP、设备、质量、库存和谱系。任一批次的冻结及解冻在相关工具内一致可见 | P1–P3 |
| F09 | 面向 Agent 的业务动作 | 派工、开工、报工、隔离、复检、处置和关单有明确前置条件，查询可解释阻塞原因 | P3 |
| F10 | 事务、并发与重试 | 同一请求重试至多产生一笔实绩。并发领料不会超扣。版本冲突、校验失败与提交异常均有可验证的结果 | P3 |
| F11 | 追溯和纠正 | 基于实际投入与产出记录进行正反向谱系查询，冲销或补正保留原始证据 | P3–P5 |
| F12 | 重放与评测隔离 | 同场景、模型版本、种子和相同控制与动作序列可重放。Agent 看不到未来事件、根因标签与评测断言 | P0、P2–P6 |
| F13 | 三行业完整场景 | 汽车零部件 CNC、电子装联 SMT、工业设备装配均通过端到端验收，且可在同一连接切换 | P3–P6 |
| F14 | 行业扩展 | 使用相同契约扩展钣金和线束场景，分别验证套料余料谱系和替代件与测试返工 | P7 |
| F15 | 运行、前端验收与维护 | P0 起可启动验收台，每个里程碑的已开放流程均可用。feature map 驱动 Playwright 和集成回归，记录 mock 或正式实现证据。具备资源预算、生命周期、诊断和版本兼容测试 | P0–P7 |

## P8B–P15 需求细化

沿用 Fxx 编号。下表规定扩展阶段的验收目标，用例入口由 feature map 登记，执行状态以验收报告为准。P8B 的查询和下达预检已有执行证据，其他子阶段随契约冻结登记可执行用例与结果。

| 特性 | 扩展验收目标 | 阶段与去向 |
|---|---|---|
| F02、F04、F09 | 以五个既有场景及跨车间等补充样例审查分层、覆盖和粒度。公共项至少有两种独立工艺复用同名及同语义契约的证据，保留各场景差异与不适用理由 | P8B–P9D，见 [分层审查](MCP_LAYERING_REVIEW.md) |
| F08–F11 | 以工单、工序、质量、主数据、库存和谱系验证公共闭环。制造相关收货、备料、冻结、处置和纠正能查询阻塞及结果。版本、实际投入、台账与谱系可对账 | P8B–P9D，见 [公共验收门槛](acceptance/COMMON_MES_GATE.md) |
| F13、F14 | 行业、履约策略、车间工艺可分别配置。五行业配置覆盖跨班执行、拒绝和恢复。跨车间样例验证合批、拆分、受影响对象冻结及其余订单继续流转 | P10 前先完成最小跨车间门槛；P10–P15 深化并总签收 |
| F01、F02、F05、F12、F15 | 长周期操作沿用同一 run 的服务端时钟、事件游标与业务记录。公开发现、描述、直接调用和错误保持制造语义。各批验收台可运行已交付流程，临时适配器有可验证的替换计划 | P8B–P15，见 [长期运营验证](LONG_RUNNING_MES_VALIDATION.md) 与 [验收与替换计划](TEST_AND_MOCK_PLAN.md) |

MES 设置 MCP 保留为内服配置待办，工具权限、影响预览、生效和回滚签收范围待细化。 [扩展计划](MES_EXPANSION_PLAN.md)

## 双主轴需求与验收目标

授权来源为项目方确认的双主轴范围，以及本次统一架构范围审查请求。设计依据见 [目标与边界](DESIGN.md#目标与边界)。

- **F01、F05、F06、F08、F09、F12 · 默认模拟测试。** 未指定外部系统时，AgentNexus 能使用 Mock MES，从 DES 生成的业务事件识别受影响工单，完成受控处置并复查状态。按相同场景、版本、种子和操作序列重跑可核对结果。首条串联场景以制造任务和状态为验收单位，控制侧保留仿真证据。
- **异构连接与本体对齐 · 待排期需求。** AgentNexus 能用同一只读业务意图经两种异构适配实现查询工单。结果可追溯到源系统和源标识，无法对齐的业务状态显式返回，外部连接不可用时保留可诊断错误。首期非目标为生产写入、全量本体和厂商覆盖承诺。进入交付时分配 Fxx 和阶段用例 ID，并登记自动化入口。
