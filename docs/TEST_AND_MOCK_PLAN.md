# 前端验收、Mock 替换与回归计划

## 双主轴验收证据

短期分别记录三源工单查询和同一 run 制造闭环的结果。外部线区分夹具回归、授权实例实测和 AgentNexus 串联。Mock 线记录场景及模型版本、run、种子、MCP 调用、DES 事件和最终台账，并验证重放。短期过后用这些证据做跨线设计审查。中期末段启用共享的工单读取一致性用例，后期分别签收新增 MES 与 Mock 对接。阶段切片冻结时将用例和执行入口加入 feature map。 [阶段与准出](IMPLEMENTATION_PLAN.md#双主轴路线与准出)

## 快速搭建端到端环境

P0 首个开发任务即搭建一条可重复启动的竖切链路。用 Rust HTTP 宿主提供静态介绍页和浏览器验收台，预留与产品相同的工具调用边界。浏览器通过测试专用会话调用 Rust HTTP 桥，桥通过真实 MCP stdio 连接 Rust 服务。浏览器 UI、HTTP、MCP、错误封装和本地状态都走实际路径。初期先提供最小场景、工具发现、查询、写入及复查，后端未开发的业务能力接入 Rust mock adapter。

- 起步交付单条本地启动命令、固定夹具、一条 Playwright 测试命令和 CI 配置。开发者能渲染页面、重置测试数据、运行流程并复看 trace。
- 验收台支持选择运行模式、打开或切换场景、搜索工具、查看 schema、填写请求、查看结构化响应和比较动作前后状态。场景观测包含当前服务端虚拟时钟及游标，时钟控制按权限开放。
- 验收台用于开发、演示和用户测试。生产工具仍由 AgentNexus 调用。介绍页持续记录当前可用流程及证据状态。
- 每个里程碑交付时，验收台须能完成当期及此前已开放的完整流程。后续能力的页面与交互可以提前开放，通过契约兼容 mock 完成正常、异常和恢复测试。页面显示当前 adapter 与目标版本。
- Playwright 通过浏览器实际提交请求，常规验收用例不使用浏览器路由拦截代替后端。固定时钟演进由测试控制请求和后端规则触发，断言等待可观察状态，避免使用固定睡眠同步。

## Mock 开发与替换

产品本身模拟制造业务。下表中的临时 mock 指开发阶段用于填补未交付模块的 adapter。替换完成后，合成工厂和仿真行为仍是产品能力。

| 阶段 | 开发与启用的临时 mock | 替换与签收条件 |
|---|---|---|
| P0 | 最小场景、可查询且可重复写入的 Rust 状态 adapter。可注入延迟、校验拒绝与重启，以便从验收台走完端到端流程。 | Rust MCP 的真实初始化、发现、读写及持久化路径接替既有 Python 探针。Rust 探针通过协议比较与重连测试后，移除 Python 启动入口和依赖。P0 探针无制造业务，须完成实际 AgentNexus 链路及 CNC 基线验收。 |
| P1 | 用试验场景和确定性工具行为演示 CNC、SMT、装配切换。设备观测、生产写入、时钟由独立 adapter 提供。 | Rust 场景注册表、实例隔离和工具搜索接管入口。相同浏览器流程能跨两个 run 复查隔离结果。行业模型可继续标记为临时。 |
| P2 | 通用场景测试可使用最小模型包，复杂业务记录继续由 mock adapter 提供。 | 生产路径切换到 Rust DES 的权威时钟、按规则抽样的事件调度和重放，注册 CNC 模型包。用真实时钟和事件游标通过回归。保留最小模型作为测试夹具。 |
| P3 | SMT 和装配继续用可维护的合成夹具演练。 | CNC 与公共 MES 行为接入 Rust 事务存储、实绩、物料台账和谱系。用生产实现验证并发、幂等、回滚及处置后的跨工具一致性。 |
| P4 | 装配和扩展行业可使用示例适配器。 | SMT 接入实际的料卷谱系、AOI、返工、召回与隔离规则，完成对应测试后移除其占位 adapter。 |
| P5 | 可提前展示钣金和线束的模拟流程。 | 装配接入齐套、替代资格、测试台竞争及终测放行，完成对应测试后移除其占位 adapter。 |
| P6 | 仅保留隔离的故障注入和兼容测试用夹具。 | 三行业交付门槛在正式模拟实现上跑全套。若早期扩展演示仍可访问，须明确标记其 mock 状态。 |
| P7 | 用固定用例和故障注入辅助回归。 | 钣金、线束替换占位 adapter。五行业正式测试齐备后，清理占位配置及未使用的契约。 |

P8B/C 临时复用现有 BOM、路线与库存夹具。P9A 替换为版本主数据和工单快照，P9B/C 替换为批次库存与移动台账，P9D 签收跨域联动。每批保留替换前后的契约与回归证据。 [公共验收门槛](acceptance/COMMON_MES_GATE.md#临时依赖与验收执行)

每个临时 mock 在 feature map 关联其实现版本、适用用例、替换阶段和正式 adapter。两种实现使用同一份输入输出 schema 和同一组共享契约测试。替换时并行运行兼容测试，核对业务状态、错误、游标和副作用，再将正式模式作为对应阶段的默认。验收或回归发现行为差异时按 [需求清单](FEATURES.md) 修正并复跑。正式模式缺失 adapter 时显式失败，禁止自动回退到占位 mock。

## Feature map 驱动自动测试

[feature-map.toml](feature-map.toml) 是初始机器可读映射。它覆盖设计特性与验收用例，当前记录的是计划，测试脚本和结果由各阶段交付。P0 实现自动执行器和 CI 门槛：

1. 校验特性 ID 与 F01–F15 一致、P0–P7 所有验收用例均有映射、用例 ID 唯一。执行器按目标阶段选中当期和此前应通过的用例。
2. 在用例接入时登记测试 ID、测试入口、必需层级、adapter 模式与替换阶段。用例可关联 Playwright、Rust 集成、模型重放或实际 AgentNexus 验证。浏览器可执行用例由 Playwright 自动跑，协议、并发、事务和重放同时由 Rust 测试提供精确断言。
3. 执行器根据 feature map 启动验收环境并调用 Playwright 与 Cargo 测试，核对实际用例 ID、执行数和结果。Playwright 使用稳定测试 ID，失败产出 trace、截图和结构化报告。AgentNexus 实测等外部依赖用例记录实际客户端版本与证据。
4. CI 将测试报告与预期覆盖矩阵比对。缺映射、缺脚本、无测试被选中、跳过、阻塞或结果缺失均不能签收该阶段。临时 mock 可提供前端覆盖证据，正式后端特性的通过证据必须来自计划替换后的实现。
5. 将每次结果关联到代码提交、环境、运行模式、场景/模型版本、种子及 CI 工件。特性或验收条件改变时，同步维护需求、阶段验收、feature map 与测试。阶段发布必须通过本阶段和既有功能的全量回归。

## 各里程碑通用前端验收

P0–P8B 的浏览器用例已纳入 feature map。后续批次按同一机制登记当期流程和前序回归。前置为按本阶段说明启动服务、加载干净测试夹具并提供当前发布场景清单。Playwright 按地图打开介绍页与验收台，进入所有已开放功能，完成当前阶段的主链路及错误后的恢复，并复跑先前里程碑的流程。断言导航、校验提示、服务端结构化响应、前后状态、运行模式与发布说明一致。留存 Playwright 报告和后端调用轨迹。具体制造断言沿用 [阶段用例](acceptance/README.md)。

| 用例 | 首要浏览器流程 |
|---|---|
| P0-UI | 从首页进入验收台，发现、读写、修正非法输入并复查已提交状态 |
| P1-UI | 交替打开两个场景，搜索、查看契约、执行并复查运行隔离 |
| P2-UI | 查看共享时钟，推进及复跑相同输入，显示模型和游标 |
| P3-UI | CNC 下达、执行、检验、处置并查谱系 |
| P4-UI | SMT 追溯召回与复检后的状态 |
| P5-UI | 装配齐套、替代件、终测及完工 |
| P6-UI | 单一会话切换三个行业并复跑已交付流程 |
| P7-UI | 钣金余料与线束返工处置，并回归五行业 |
