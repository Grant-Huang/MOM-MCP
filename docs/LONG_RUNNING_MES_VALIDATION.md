# 面向 Agent 长期运营的 MES 测试模拟

本项目用 mock 模拟真实 MES 的业务行为，目标是检验 AgentNexus 能否在共享工厂状态上持续处理生产、库存、质量、资源和异常。公开 MCP 使用制造业务契约，内部仿真控制、随机种子和评测答案留在受信控制面。

## 两层交付标准

| 层级 | 交付内容 | 签收 |
|---|---|---|
| P10 前公共闭环 | P8B–P9D 的工单执行、质量、主数据、库存和谱系 | 同一 CNC run 走通跨库位、跨批次拒绝、纠正和恢复，SMT 用同一契约验证复用 |
| 长期运营测试 | 多班次连续经营、异常叠加、未决事项接续、配置变更和多角色协作 | Agent 在无场景重置的连续运行中完成任务，关键业务、权限与账实不变量持续成立 |

83 项是公共闭环的首轮候选。P8/P9 依据 [跨场景审查](MCP_LAYERING_REVIEW.md) 确定公共集，长期运营覆盖由业务任务矩阵决定。五行业已有单场景测试继续回归。既有 68–106 人周估算以当时的五行业能力扩展为范围，长期运营新增范围和工期另行估算。

## 目录扩展审计

| 能力域 | 长期运营应能测试的任务 |
|---|---|
| 工作入口与交接 | 跨班待办、逾期任务、需审批项、未处理异常、在制与排产快照、事件续读与交接 |
| 计划与执行 | 工单插单和延期、有限资源下的优先级与改派、跨班暂停恢复、工艺变更影响评估、报工与实绩对账 |
| 库存与补给 | 库位与批次不足、预留争抢、部分收货、调拨在途、盘点差异、替代与跨库退料、补货事件处理 |
| 质量与谱系 | 部分接收、冻结查询、跨工单召回、让步审批、返工工艺生效、完工后追溯及纠正 |
| 资源与维护 | 人员、工具和设备资格及到期、换班、停机、维修、校准、能力恢复和重新排队 |
| 管理与外部回执 | 区分角色和审批、查看配置差异与生效范围、核对 ERP/WMS/QMS 模拟回执、版本不匹配、重试与对账 |

结合 Carbon 的生产、质量、库存、物料和资源目录逐项审计，并以 qcadoo 的切换与纠正、OpenMES 的版本与质量处置、WebErpMesv2 的行业账务追溯补足验收。每项记录参考能力、对象、生命周期、可调用工具、权限、失败恢复、业务不变量及验收 ID。数量在目录审查后重新统计。对单字段编辑、完全等价查询及行业别名按业务语义去重。

## 连续运行签收

1. 先交付跨班，再验证跨日和多日。用一个持续的工厂 run 承接滚动订单、在制品、在途物料、未完检验和占用资源，交接与恢复沿用同一业务状态和游标。
2. 验证叠加异常。例如插单与到料延期同时发生，关键设备停机，之后又收到针对已投入批次的召回。Agent 按业务工具取得事实、调整处置、说明阻塞原因并保留证据。
3. 验证执行中的配置或版本变更。既有工单快照保持，后续工单按生效规则使用新版本。设置 MCP 仍单列待办，后续细化权限、生效、回滚及审计。
4. 验证多 Agent 并发、重复或乱序回执、连接重建和跨班交接。分别核对库存不超扣、质量门禁不绕过、资源不超配、有效谱系无断链及未决事项可恢复。
5. 使用固定种子为关键事件构建可复跑的回归，同时用多个种子验证策略对时序变化的适应性。评测侧独立观察任务结果、处理时效、异常恢复与业务不变量。MCP 客户端仅获得其权限和已发生时间允许的业务事实。

P8B 起登记任务矩阵和连续运行依赖。P10 前的公共闭环门槛保持有效。公共能力落地后，先用 CNC 建立跨班运营基线，再逐行业扩展。五行业长期运营签收单独记录，公开工具契约统一使用业务语义。
