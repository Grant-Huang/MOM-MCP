# 模拟 MES 设置设计

## 目标和范围

让配置 Agent 在模拟环境中查看当前设置、提交候选变更、确认影响、启用版本和纠正误配置。首批以工作中心与班次为验收对象。后续依次评估组织与工厂结构、编号与单位、工艺和质量默认策略、模板导入。工单快照仍保存下达时的制造定义。

## 权限和作用域

配置操作通过独立的受信接口面向内服配置 Agent。普通生产 Agent 的搜索、描述和直接调用入口均保持权限隔离。服务根据受信调用身份解析目标作用域，工具参数中的站点或变更号仅用于选择对象。配置读取、编辑、启用和审计分别授权。该边界依赖服务端可验证的身份或隔离实例。生产接入沿用现有场景运行接口。

## 版本与生效

每个作用域保留一个已启用版本。草稿记录基线版本及变更。校验和预览输出候选摘要、影响对象及阻塞原因。启用事务核对基线版本、候选摘要和授权，同时写入新快照与审计。并发启用仅一笔可以提交。同一幂等键和参数返回原回执。回退以旧快照创建新版本，原变更及审计记录保留。

首批启用影响之后创建的运行。已打开运行持有创建时固定的配置版本。有效班次使用工厂时区和本地时间定义，由服务端仿真时钟决定覆盖区间。业务调用方可以选择场景和版本，仿真时钟由服务端持有。跨午夜班次、时区转换、工作中心与工艺能力的引用、重复班次和工作中心失效属于首批校验范围。

## 首批候选工具

| 工具 | 行为 |
| --- | --- |
| `get_mes_settings` | 查询授权作用域的活动版本和支持的设置。 |
| `create_mes_settings_draft` | 从指定基线提交工作中心与班次候选变更，可返回草稿标识。 |
| `validate_mes_settings_draft` | 返回字段、引用和时间规则的校验问题。 |
| `preview_mes_settings_draft` | 返回候选摘要、受影响的运行入口和不能启用的原因。 |
| `activate_mes_settings_draft` | 校验权限及基线，并原子启用已预览的候选。 |
| `restore_mes_settings_version` | 为授权作用域创建并启用恢复版本，保留历史。 |
| `list_mes_settings_changes` | 按作用域和游标查询变更记录，包含操作者、原因和前后版本。 |

工具名和数量是首批候选。实现阶段在接口与验收同时冻结时再计入发布目录。

## 实施与验收顺序

1. **读取与写隔离。** 建立机器身份边界、作用域、配置快照和查询。记录默认版本及审计字段，让验收台可以打开授权和未授权两种测试会话。浏览器通过服务端真实入口演练。
2. **草稿、校验和预览。** 以班次与工作中心样本覆盖合法、重复、引用失效和跨午夜情况。预览前后读取活动版本，核对它保持原值。
3. **启用、回退和恢复。** 两个会话从同一基线竞争启用，校验一笔提交、一笔版本冲突及按键回放。回退后对照配置及完整审计。
4. **生产接入。** 以机加工和按单装配测试场景交叉验证。已打开运行沿用旧配置，新运行按新班次派工。对服务端仿真时点和跨班交接做可重复断言。

实现前冻结按阶段验收编号，并接入 Rust 集成、功能映射和 Playwright 回归。早期验收台可使用同契约内存存储，落地持久化时复跑同一组断言。生产工具隔离必须同时验证搜索、描述和直接调用。
